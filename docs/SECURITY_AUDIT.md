# Security Audit

- Date: 2026-11-24
- Scope: application code, built manifests, build configuration, wrapper, CI workflow, Git history, and all resolved Maven dependencies for version 2.0.0.
- Method: manual review, gitleaks with redaction over all commits, Android Lint, `aapt2` inspection of built APKs, wrapper and distribution checksum comparison against Gradle's published values, action pin comparison against upstream tags, and an OSV query.

## Results

| Check | Result |
| --- | --- |
| Secrets in Git history (gitleaks) | None found |
| Injection, XSS, CSRF, and `eval` | Not applicable: no web, SQL, or network surface in the app |
| Authentication and 2FA | Not applicable: no accounts, server, or contact form |
| Cryptography and hashing | Not applicable: the app stores no credentials and does no hashing or encryption |
| OSV advisories, 257 resolved packages across app, test, and build-tool classpaths | 0 reported on 2026-11-24 |
| Android Lint | 0 errors, 3 warnings (version recommendations only) |
| Built manifest permissions | Only the app-private AndroidX `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` |
| Exported components | Launcher activity, and the AndroidX profile receiver guarded by the `DUMP` permission |
| Gradle wrapper | JAR and scripts match those generated by Gradle 9.9.2, and the JAR matches the published checksum |
| CI actions | All four SHA pins match their upstream tags, with read-only permissions |

## Fixed

| Severity | Finding | Resolution |
| --- | --- | --- |
| High | A stalled UI thread could release queued flashes in a burst, breaking the flash-rate limit | Steps are chained, with a property test under simulated stalls |
| High | Build-tool classpath resolved packages with published advisories, including one rated critical. None ship in the APK | Constrained to patched versions |
| Medium | Twelve property tests, including the flash-rate test, never executed | Fixed, and the report generator now fails on a mismatch |
| Medium | Unused `CAMERA` permission was declared | Removed; the torch API does not need it |
| Medium | Build tooling was outdated and the distribution was not checksum-pinned | Upgraded and pinned with SHA-256 |
| Low | App backup was enabled | Disabled, with exclusion rules for backup and transfer |
| Low | Torch exceptions were swallowed, so failures looked like success | Narrow handling with a visible failure state |
| Low | Camera lookup could crash at startup | Handled as no torch available |
| Low | Input length was unbounded | Limited to 256 characters |
| Low | Keyboards could learn from message input | Requested no personalized learning |
| Low | Invalid experiment options crashed with a stack trace | Validated, with a usage error |
| Info | Release shrinking was disabled | Enabled |
| Info | IDE configuration was tracked | Untracked |
